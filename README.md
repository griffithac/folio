# Folio — Book Classifier

Folio reads PDF books in the browser and uses TypeSafe Jev to suggest their subject/genre, narrower subject, language, reading complexity, and narrative setting period. The app supports multiple uploads, thumbnails, duplicate detection, search and filters, uncertainty review, manual correction, and JSON export. An original sample PDF lets testers exercise the real pipeline.

The public beta uses **one shared public workspace**. D1 retains book records, sampled text, Jev predictions, human corrections, reference labels and revisions. R2 retains uploaded PDFs. Everyone with the link can see, download, edit and remove books. The API key remains server-only. Deletion removes the shared record and PDF. Earlier browser-beta results are migrated when that browser opens the updated library; the earlier beta did not retain originals, so those PDFs must be reuploaded to attach them. Concurrent writes use revision checks to avoid overwriting another tester’s edits. This public demo is separate from the private customer workspaces needed for a commercial product.

## Run locally

Requires Node 22.13 or newer and pnpm 11.19.

```sh
pnpm install
cp .env.example .dev.vars
# Fill TYPESAFE_API_KEY in .dev.vars; never commit this file.
pnpm run db:generate  # Only after changing the database schema.
pnpm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_famous_warbound.sql
pnpm run dev
```

Apply each pending migration once per local database, including `drizzle/0001_bizarre_sage.sql` for shared books. The database is shared by dev and production previews through `.wrangler/state`. To preview the compiled Worker, copy the ignored `.dev.vars` to `dist/server/.dev.vars`, then run `pnpm run start` (normally port 8787). Deployment through Sites applies hosted schema migrations separately. Never replay migrations already applied to a database.

`pnpm run typecheck` checks TypeScript. `pnpm run test` runs offline tests with no billable requests. The SDK’s custom transport is used to verify the typed API contract.

## Hosting and configuration

`.openai/hosting.json` records the Sites project ID, D1 and R2 bindings. Preserve the ID when publishing updates. The site’s audience is public at the user’s request. Configure runtime values with Sites environment-variable tools, then deploy to apply the environment revision:

- `TYPESAFE_API_KEY`: secret, server only. The supplied project key has been configured in Sites, never in source or browser code.
- `TYPESAFE_MODEL`: `jev-latest` by default. The actual model ID is recorded with every result; pin a verified version for reproducible benchmarks.
- `CLASSIFICATION_DAILY_LIMIT`: 250 requests per UTC day across the public test site. The atomic D1 quota also counts failed upstream requests. This protects the shared project key but is not a per-person entitlement.

The public health endpoint reports only whether Jev is configured, not its credentials. Classification accepts bounded JSON, validates excerpt lengths and page numbers, rejects cross-origin browser submissions, validates every returned probability distribution and taxonomy key, and gives recoverable errors. SDK request-body logging is disabled.

## Standards research — verified October 3, 2026

A book’s subject, literary genre, language, reading complexity, and audience are distinct dimensions. There is no single standard that supplies them all.

| Dimension | Industry vocabulary or measure | Recommendation and prototype behavior |
| --- | --- | --- |
| North American publishing subjects | [BISAC, maintained by BISG](https://www.bisg.org/complete-bisac-subject-headings-list) | Use for publisher/retailer interoperability. The official currently published list is the 2025 edition. Preserve exact codes, edition, primary subject and additional subjects. BISG distinguishes free online selection from licensing the complete list for incorporation into business systems. No full BISAC list is embedded in this app. |
| International publishing subjects | [Thema 1.6, EDItEUR](https://ns.editeur.org/thema/en) | The initial pass uses 31 selected broad categories and 28 immediate-child branches. The automatic detailed pass searches all 3,422 subject nodes in 20 sections, explores multiple branches, and retains independently supported subjects with exact source passages. Official codes, headings, source version and scope notes are preserved. Qualifiers and certified catalog assignments remain separate work. |
| Library literary genres/forms | [Library of Congress Genre/Form Terms](https://www.loc.gov/catdir/cpso/genreformgeneral.html) | Appropriate if library interoperability is the goal. LCGFT describes what a work is, separately from what it is about. Keep authorized term/URI separate from subject codes. Not implemented in this beta. |
| Language | [ISO 639-1 and ISO 639-2, Library of Congress code table](https://www.loc.gov/standards/iso639-2/php/code_list.php) | Implemented for the full Library of Congress ISO 639-2 catalog: 483 language or collective entries, plus `mul` (multiple languages), `und` (undetermined) and `zxx` (no linguistic content). Three independent Choice groups run in the initial pass; conflicts receive one candidate comparison. Raw group and comparison distributions are retained. Exports use terminology codes and current two-letter codes where available. Collective labels require review; individual varieties, dialects and scripts are not comprehensively distinguished. Unsupported or unidentifiable languages remain undetermined. |
| School reading difficulty | [Lexile / MetaMetrics](https://hub.lexile.com/text-analyzer-user-guide/) and [ATOS / Renaissance](https://www.renaissance.com/edword/atos/) | Use independently obtained measures for the matching edition as benchmark references. Jev does not produce a genuine Lexile or ATOS measurement. MetaMetrics distinguishes estimated classroom ranges from commercial and certified measures. Renaissance’s ATOS analyzer and Bookfinder provide a separate route to ATOS levels. This beta reports only explicitly labeled Jev estimates. |
| Language learner proficiency | [CEFR, Council of Europe](https://www.coe.int/en/web/portfolio/the-common-european-framework-of-reference-%20for-languages-learning-teaching-assessment-cefr-) | Relevant for graded readers and second-language proficiency, not interchangeable with school grade or a general book difficulty measure. A separate optional CEFR task would need its own evaluation set and reading-comprehension rubric. Not implemented here. |

[Thema’s usage rules](https://ns.editeur.org/thema/en/5TFB) call for a primary subject, enough additional subjects to describe the work, appropriate specificity, and relevant qualifiers. Ancestor and descendant codes should not both be assigned as equivalent subjects. The current broad Choice and scoped narrower Choices are a testing prototype; it should not be presented as complete distributor metadata.

[ATOS distinguishes book difficulty, tested reader ability, and interest level](https://arhelp.renaissance.com/hc/en-us/articles/12630557859227-Levels-Book-Interest-and-Reading). A difficult text need not have mature themes, and an easy text need not be appropriate for young children. Folio’s rubric judges vocabulary and syntax, not content suitability. No age recommendation or certified score is inferred.

## What to test against

Start with a separately labeled, held-out set of real books. The synthetic sample PDF and automated code tests are engineering checks, not evidence of classification accuracy.

1. **Subjects:** use publisher-assigned Thema/BISAC metadata for the matching edition. Cover fiction genres and nonfiction subjects, children’s and adult books, hybrid genres and books outside the selected subset. Record all applicable gold subjects. Compare broad predictions with appropriate ancestors; do not count a broad match as a correct leaf assignment. Report per-category precision/recall, macro F1, fallback rate, and reviewed-versus-automatic coverage. For full taxonomy support, follow TypeSafe’s [hierarchical classification cookbook](https://docs.typesafe.ai/cookbooks/hierarchical_classification).
2. **Languages:** use verified ISO codes, include English, Spanish, French, German, CJK and RTL scripts, multilingual books, and languages outside the supported subset. Measure accuracy separately by language and distinguish mixed-language books from books containing short foreign quotations. Test the actual edition/translation, not the language of an original work. TypeSafe notes stronger performance on English in its [current model documentation](https://docs.typesafe.ai/models).
3. **Reading complexity:** cover all six estimated bands with independently measured books, and record available Lexile and ATOS values separately alongside edition, source and language. Define a comparison rule before testing; these scales are not directly convertible or certifications of Folio’s output. Have educators independently review Jev bands. For educator band labels, report weighted agreement and an ordinal error distribution, including adjacent-band errors. Do not turn model confidence into an accuracy claim.
4. **Sampling:** compare the current up-to-18-page excerpts with fuller evidence on a smaller reference set. Include front matter-heavy books, appendices, technical figures, poetry and short picture books. Investigate errors caused by missing evidence separately from model mistakes.
5. **Files and behavior:** searchable versus scanned PDFs, locked and malformed files, file-size limits, duplicate uploads, interrupted requests and reloads, unavailable API key, rate limits, exports, corrections, keyboard navigation and mobile layouts.
6. **Reproducibility:** save model ID, taxonomy version, question/rubric version, excerpt page numbers, raw probabilities, reviewer corrections and evaluation date. Keep model predictions distinct from human corrections. Tune thresholds on a development split, then report performance once on the held-out split. The default review threshold of 0.7 is a starting policy, not a validated optimum.

## Current limits

- Searchable PDFs only; OCR is not implemented. At least 200 characters must be extracted.
- 25 MB per PDF, 10 files per batch, 50 books in the shared workspace.
- PDFs of up to 18 pages use all extracted text when the evidence JSON fits 14 KB. Larger works use up to 18 distributed pages and 1,000 characters per page, including beginning/middle/ending passages within long pages. A 14 KB UTF-8 evidence budget bounds multibyte scripts. Byte guards reserve room below the provider context limits; they are not exact tokenizer counts.
- Six estimated literacy bands: early reader (K–2), elementary (3–5), middle school (6–8), high school (9–12), college/adult, specialist.
- The detailed subject search explores at most six candidate paths per depth and two broader-parent fallback rounds. Qualifiers use four paths per dimension, separately retained broader candidates, and source checks. Search pruning is disclosed; full taxonomy reachability does not guarantee exhaustive per-book recall.
- PDFs and results persist across browsers in the shared public workspace. This beta has no user accounts or edit permissions; anyone with the link can change records.
- Original PDFs uploaded after the shared-workspace update are retained. Earlier results require the same PDF to be reuploaded to attach an original.
- Confidence is provider output, not a measured success rate. Human corrections do not overwrite the original judgment.

The integration uses [TypeSafe’s official JavaScript SDK](https://docs.typesafe.ai/sdk/javascript) and [agent skill](https://github.com/typesafe-ai/skills/blob/main/skills/typesafe-ai/SKILL.md). The skill was fetched into `.agents/skills/typesafe-ai/SKILL.md` for this project.

## One-pass questions and context strategy

Each app classification starts with one `systemOne` request with 72 independent questions: primary subject, three dominant-language partitions, literacy complexity, story setting, 28 scoped subject branches, book form, intended audience, assumed technical experience, 21 technical-language presence questions and 14 computing-topic presence questions. Questions cannot read another answer. The app consumes only the narrower answer associated with the chosen primary subject. Leaf parents without children stay at their own code. Unspecified subcategories remain unassigned; lower confidence routes to human review. A conflicting language result adds at most one dependent comparison, counted against the daily quota; other initial results survive a failed comparison. Automatic SDK retries are disabled for this endpoint so each upstream request reserves quota. The context checks include all fanout questions. Repeated code-owned rules are stored once in `evidencePolicy`, and the title is omitted from model state to avoid title familiarity cues. The 14 KB extraction budget is retained. Jev's documented limits are 64k tokens total and 32k for state plus the longest question ([models](https://docs.typesafe.ai/models)); English is strongest.

Story setting includes prehistory, ancient BCE, early CE, medieval subdivisions, centuries, two nineteenth-century halves, each twentieth-century decade and contemporary decades, plus broad fallback periods, the future, multiple periods, imaginary/timeless settings and uncertainty. The question prefers the finest period supported by the excerpts. These are prototype temporal bins, not full Thema time qualifiers. Dates describe narrated events, not publication.

## Full language catalog and conflict handling

`lib/data/ISO-639-2_utf-8.txt` preserves the official [Library of Congress UTF-8 source](https://www.loc.gov/standards/iso639-2/ISO-639-2_utf-8.txt); collective flags use the [LOC FAQ](https://www.loc.gov/standards/iso639-2/faq.html) and [MARC language list](https://www.loc.gov/marc/languages/language_name.html), including creoles/pidgins and sign languages. The parsed catalog records its retrieval timestamp and SHA-256 hash, unmodified English/French names, aliases and bibliographic/terminology codes. The reserved private-use range `qaa–qtz` is not a language and is excluded. Current two-letter mappings are retained; the deprecated Bihari `bh` is not exported. Older result labels remain readable.

Each of three stable groups has 161 language/collective choices plus multilingual, no linguistic content and outside-group/unknown outcomes: 164 options, below [Jev’s 255-option limit](https://docs.typesafe.ai/primitives/choice). Dominant natural prose is separate from programming languages, mentions and incidental quotations. A specific language is preferred to a collective grouping. `mul` requires substantial multilingual prose with no dominant language; `zxx` requires no natural linguistic content.

One consistent candidate uses its actual group distribution. When several groups select the same special code, the least confident actual answer is displayed. Probabilities normalized over separate groups are never merged into a fabricated global distribution. Conflicting candidates receive one separate comparison against the original evidence, including an undetermined option. Missing quota, malformed output, service failure or model drift preserves the other labels and leaves language undetermined for review. A derived undetermined fallback has no provider distribution or confidence claim. All group answers, any valid comparison, model IDs, provenance, request count and decision basis survive shared persistence and JSON export.

`node --experimental-strip-types scripts/language-benchmark.ts` runs 15 original developer passages with Jev 1.13.0. All expected language codes matched in this run; five needed a comparison. Low-confidence group or comparison answers remain review flags. These author-supplied development labels are not expert validation of books, every language or the entire catalog. `/testing` links the passages and raw language judgments. `scripts/primary-regression.ts` separately reruns the eight existing sampled public-domain fixtures and tests a printed malicious instruction, preserving the earlier public report and book records. The full-text benchmark now resolves language conflicts per chunk and records character-weighted chunk-label votes separately from non-language probability averages; these votes are not provider confidence.

## Detailed subjects across all books

New classifications automatically search the complete unmodified [Thema 1.6 source](https://www.editeur.org/files/Thema/1.6/v1.6_en/20250410_Thema_v1.6_en.json), covering 3,422 subject nodes in 20 sections. Existing books can use “Find detailed subject” or “Refine subject again.” The source retains all original qualifiers, exact codes, canonical headings and scope notes and is attributed to EDItEUR under its [license](https://doi.org/10.4400/nwgj). The copied license is in `lib/data/EDITEUR-LICENSE.txt`; supplementary Folio tags remain separate.

The detailed pass uses up to six parallel candidate branches at each depth, with a separate section-applicability judgment so secondary subjects are not forced to compete as exclusive labels. Choice distributions guide the bounded search. Length-normalized path scores rank candidates and are **not** calibrated correctness probabilities. Root sections are never assigned as book subjects. Multiple verified descendants replace redundant ancestor suggestions.

Final candidates must pass two separate Jev Noul checks at the same pilot threshold of 0.8: substantial book-level subject support and direct support in the selected source passage. Code selects and copies exact passages by PDF page and source offsets; it never asks Jev to generate a quote. Shared-record validation rejects fabricated quotations, invalid official paths, invented headings, inconsistent assignments and mismatched evidence. Artificial sampling-gap markers are excluded from quotations. A failed narrow subject can fall back to an independently checked official parent without lowering the support threshold. Children's codes require evidence of a younger audience, not merely the word “textbook.” These are model support checks, **not independent expert validation**.

The search uses at most twelve requests, all counted against the public daily quota. Context guards and automatic question batching bound each request. A model-version change during a search fails closed. Unresolved or pruned alternatives remain visible and route the book to review. Review approval is kept separate from raw candidate probabilities and external reference labels. This is a multi-subject suggestion system over the full subject taxonomy, not a certified or guaranteed complete publisher catalog record.

`node --experimental-strip-types scripts/subject-benchmark.ts` runs original developer regression fixtures across all twenty subject sections plus mixed subjects, printed prompt injection, and uninformative front matter. It requires the ignored server key, pins Jev 1.13.0 by default, records actual responses/usage, and caches by exact model/state/questions in ignored `outputs/subject-response-cache`. Developer fixtures demonstrate workflow coverage and known regressions; they do not estimate accuracy on real books.

Supplementary metadata includes form, suggested intended audience (based on selected ONIX audience concepts), and independent technical tags. Natural language stays separate from code languages; HTML and CSS are explicitly markup/style languages. The 0.7 yes-probability display threshold is an unvalidated pilot policy. Audience is not a content-suitability guarantee. Technical prerequisites and prose difficulty are separate fields. ISBN, edition, publication date, publisher and series should come from verifiable source metadata; the app does not invent them.

## Reference evaluation and review

The validation page uses `reference-evaluation-v3`. Scalar agreement includes every book with an eligible reference label, including missing predictions. Reading-band distance excludes missing or invalid bands and reports its separate comparison count; an absent subcategory is not silently treated as an explicit “Unspecified” answer.

Reference records can contain a complete or partial multi-label Thema 1.6 subject set, separately from the optional primary subject. Complete sets enable exact-code micro precision/recall/F1, per-code counts and macro F1 over the observed reference/prediction union (including extra-only codes). These follow the [standard precision, recall and averaging definitions](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_recall_fscore_support.html). Undefined ratios remain null. Missing searches and explicit abstentions retain missed reference labels; an unrun search cannot earn an exact empty-set match. Broad section matches and actual official-ancestor relationships are diagnostics, never exact-code credit. Partial and legacy primary-only references show coverage of known labels only; their extra predictions are unjudged and excluded from complete-set metrics.

Verified references require a named independent reviewer, role, method and review date. Edition references require an explicit edition-match check; verified language and reading-band labels must describe the uploaded edition or translation. Reviewer identity and expertise are self-attested in this public beta, not authenticated or certified. Legacy verified flags without review provenance are excluded from verified metrics. All eight existing catalog mappings remain provisional; no independently adjudicated expert corpus has been established.

Review records disclose whether labels were established before seeing model predictions. Optional work grouping keys connect editions and translations; Folio warns if a group, or identical PDF fingerprint, crosses development and holdout. This check cannot establish an untouched holdout by itself. Mixed model versions are disclosed. “Export validation report” downloads the current shared report from `/api/validation?split=all` (also `development` or `holdout`), with its timestamp, metric version, counts, per-book mismatches, warnings, raw model outputs, original excerpts, source references and review provenance. The link is shareable; it is a fresh snapshot rather than an immutable benchmark run. Human corrections and suggestion approval never alter the raw prediction scores.

## Public-domain pilot

The current report compares eight works spanning children’s fiction, fantasy, literary fiction, memoir, romance, science fiction, mystery and horror. Searchable text PDFs and sampled Jev results are preloaded in the shared workspace. Generated PDFs omit illustrations and the Gutenberg wrapper. Project Gutenberg lists their public-domain status in the USA; that is not a claim of worldwide status.

`/testing` shows actual Jev 1.13.0 method comparisons, per-dimension agreements, disagreements, evidence coverage and request counts using the v3 questions. Every extracted baseline character is covered by consecutive chunks when it cannot fit one request. Probabilities are averaged by character count; this aggregate support is not provider confidence. Full coverage in chunks has its own loss of cross-chunk context. Method agreement is not accuracy. Setting disagreements for Austen and Wells and reading-band disagreements for French prose and Sherlock Holmes illustrate why the sampling policy needs broader evaluation.

`/validation` compares uncorrected predictions with separately recorded reference labels. Initial catalog/publisher mappings are **provisional**, pending independent review; no expert-validated accuracy is claimed. A reference records its source, scope, edition, review status and development/holdout split. Only supplied verified labels enter verified-reference metrics. Published ATOS/Lexile measures are shown separately, without conversion to a Jev band. Initial ATOS references include Peter Rabbit (4.2), Alice (7.4), Pride and Prejudice (12.0), and The Time Machine (7.4), with official Renaissance links and edition-match caveats. They do not certify these generated Gutenberg PDFs.

## Backlog

### Official subject qualifiers — implemented for review

The qualifier stage covers all 5,765 official Thema 1.6 qualifier nodes in six families: place, language discussed, time period, educational purpose, interest and creative style. All scope notes and official parent relationships are retained. The language a work discusses is separate from its ISO text-language result. Interest age is separate from reading complexity.

New classifications run qualifier refinement after source-backed detailed subjects. Existing books have a **Find qualifiers** action. The server loads the saved book and its current revision; it does not trust client-supplied subject headings or evidence. Every assigned qualifier requires book support, a compatible subject relationship, and an independently checked exact source quotation, each with a pilot 0.8 support gate. Routing placeholders are never assigned. Explicit age compatibility and one base interest age are enforced in code. Assignments, raw decisions, passage choices and failed candidates persist in the shared workspace and exports; human approval preserves these diagnostics.

Independent questions run together where context permits. Search uses up to four paths per family, ten levels and 36 requests, with adaptive option groups and two independently verified fallback rounds. Broader terminal candidates are retained outside the beam when their descendants remain active, so redundant ancestors do not consume slots needed by distinct periods, places or purposes. At most 24 separately retained broader candidates, 72 verified candidates and 24 assigned suggestions are kept; truncation is disclosed as pruning. Quota reservations count actual upstream attempts, including failures; rejected reservations do not increment request counts. Timeout, model changes, malformed answers and exhausted budgets produce explicit partial/unavailable results for review. Existing labels and subjects remain saved. Pruning, uncertain dimensions and incomplete source evidence can miss qualifiers; full catalog reachability is not exhaustive prediction or proof of correctness.

The `source-facts-v1` evidence method computes numeric calendar ranges from 254 official period headings and literal matches for official names and listed aliases. Historical years have no zero; explicit BCE/CE/BC/AD markers and eras shared within bounded written ranges retain exact source offsets. Bare four-digit numbers remain possible years, not date claims. Numeric quantities, metadata, negated details and incidental names cannot bypass the semantic source, subject and quotation gates. Quote-only checks recompute facts from their exact quotation, rather than borrowing matches from other passages; adaptive quote groups keep independent checks within the context budget. A missing literal match does not exclude other semantic evidence. At most 12 matches per candidate are retained with total-count/truncation disclosure; public persistence recomputes them against saved source text and rejects forged facts. Older runs remain readable and can be rerun. The review panel and exports retain these diagnostics.

Reproduce the 16 original developer passages with `node --experimental-strip-types scripts/qualifier-benchmark.ts`; the public report preserves missing anchors, excluded-code violations and unexpected families as well as assigned codes, source quotations and raw probabilities. It covers mixed periods, the BCE/CE boundary, named exams and explicit interest age, alongside incidental names, metadata, quantities, negations and printed commands. Descendants satisfy required anchors and violate excluded anchors. Same-family extra codes are not exhaustively adjudicated. These fixtures are not independent expert validation. Further work includes wider book-level evaluation, qualifier reference labels, holdout metrics and calibrated support policies.

Qualifier references can now be recorded independently for each of the six dimensions. Complete dimension references enable exact-code micro precision/recall/F1, macro F1, per-code and per-dimension counts; partial lists provide only known-code coverage and do not judge extra predictions. Exact agreement across all six dimensions requires every dimension to be completely referenced. Missing, partial and unavailable prediction runs retain missed labels and never count as an explicit empty match. Official ancestor differences are reported separately without exact-match credit. Optional per-qualifier subject relationships have their own completeness and metrics, so a correct code attached to the wrong subject is a separate error. Only supplied relationship references judge links. Verified qualifier references require reviewer provenance and a matched uploaded edition/adaptation. Provisional, development and holdout results remain separate; review approval and corrections never change raw predictions. The validation export includes full qualifier judgments, source matches, routing and references.

`public/qualifier-reference-pilot.json` contains a partial, work-level place-code crosswalk for Dracula from [Gutenberg catalog subject headings](https://www.gutenberg.org/ebooks/345) to the official [Transylvania](https://ns.editeur.org/thema/en/1DXR-RO-ZT) and [Whitby](https://ns.editeur.org/thema/en/1DDU-GB-EYKW) codes. It uses catalog subjects rather than Gutenberg’s automatically generated summary or publication date. Reproduce with `node --experimental-strip-types scripts/seed-qualifier-references.ts <site-origin>` after deploying the updated reference schema. The seed requires a unique matching title/source, respects current revisions, and skips existing reviewed, holdout, edition-specific or qualifier references. This developer crosswalk is explicitly provisional, incomplete, not independently expert-reviewed, and not a claim that the generated edition has been matched.

### Support common book formats for upload — planned

Expand uploads beyond the current searchable-PDF support, using one classification and review workflow across formats.

- **First priority:** EPUB, DOCX, TXT, HTML, Markdown, RTF and ODT, alongside PDF.
- **Additional ebook formats:** FB2 and legacy MOBI, AZW and AZW3. Assess KFX compatibility before committing to support.
- **Image-based books:** scanned PDFs, DjVu and comic archives (CBZ/CBR), with OCR and explicit handling of image-dependent content.
- **Legacy documents:** assess DOC conversion for authors and publishers with older manuscripts.

Acceptance criteria:

1. Validate the actual format, provide clear unsupported/corrupt/encrypted-file errors, and enforce file, archive-entry and extracted-content limits. DRM-protected ebooks require an unprotected copy; DRM removal is outside scope.
2. Retain the original upload and normalize text, metadata and structure for the shared classification pipeline. Evidence links must preserve real page, chapter or section locations rather than invent PDF page numbers.
3. Apply the existing context limits, sampling strategy, detailed subject search, shared persistence, exports and deletion to every supported format. Report extraction gaps and OCR uncertainty for review.
4. Compare classifications of the same book across formats using public-domain fixtures, including Unicode, illustrations, tables, footnotes and malformed files. Record differences separately from sampling-versus-full-text comparisons.

## Completion audit for the robust-classification goal

Implemented and checked: complete subject taxonomy coverage; multiple candidate paths and subject suggestions; canonical-code validation; independent dimensions in one initial pass; exact source passages and support gates; bounded context and request budgets; official parent fallback; shared persistence, optimistic concurrency, deletion and raw-result/reference separation; reproducible regression and sampling tests; multi-label subject and per-dimension qualifier reference evaluation with missing-prediction accounting, separate subject-link evaluation, review provenance and split-leakage warnings.

Still required before claiming exhaustive, validated classification: independently adjudicated multi-label reference books and untouched holdout evaluation; precision/recall and unsupported-label analysis by subject and language; broader sampling/full-text evaluation for long and uneven books; independent qualifier evaluation and missed/unsupported-code analysis; independent evaluation across the expanded ISO 639-2 catalog and finer individual-language/script handling where needed; reading-band validation independent of audience and technical prerequisites; handling scans, complex layouts, missing text and image-dependent works; and measured/calibrated review policies. The active goal remains incomplete. No test suite or confidence threshold alone proves universal correctness.
